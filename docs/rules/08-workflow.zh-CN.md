## 导入前

- **必须**由负责人提供或明确批准成熟 SVG。
- **必须**在仓库外完成背景、辅助线、颜色和复杂结构清理。
- **必须**确认文件名和元数据语义准确。
- **禁止**把草稿、截图重绘或未经确认的设计导出物放入 raw。

v1 每个名称只接收一份 `24×24` Canonical SVG。多光学母版不属于当前导入流程。

- **必须**让每一份 Canonical SVG 单独获得负责人批准。
- **禁止**从现有文件复制或自动生成尺寸变体。

## 准入审核

审核同时包含结构检查和视觉检查：

1. 验证 24×24 根画布和透明背景。
2. 检查 20×20 目标区、描边外缘和坐标对齐。
3. 在 16/20/24/32px 下检查同一 Canonical SVG。
4. 与同分类图标比较视觉重量、圆角和负空间。
5. 确认元数据、分类、标签和别名完整。

- **必须**在无法无损解决结构问题时停止导入并请求新文件。
- **禁止**为了通过生成而自动修复负责人确认的图形。

## 生成边界

生成器负责只读解析真源并产生：

```text
@uplus-icon/core
@uplus-icon/react
@uplus-icon/web
```

- **必须**让所有包共享同一 Core Definition。
- **必须**保证生成结果稳定、可重复且不依赖手工补丁。
- **必须**让所有包消费同一单母版 definition。
- **禁止**从框架包反向生成或修改 SVG 真源。
- **禁止**由生成器合成尺寸变体。

## 包体与兼容性

- **必须**为每个图标保留真正的逐图标入口。
- **必须**让单图标入口只包含对应 definition 和运行时。
- **应该**让固定名称消费者使用具名组件或逐图标路径。
- **可以**让数据驱动场景使用包含完整注册表的 dynamic 入口。
- **必须**把改名、删除和类型变化作为公共 API 变更评估。
- **禁止**让导入单个图标时包含完整图标集。

## 提交验证

```bash
npm run generate
npm run typecheck
npm run build
npm run check
```

至少确认：

- **必须**通过 SVG 结构、元数据和生成数量检查。
- **必须**通过 Core、React、Web 和网站构建。
- **必须**通过 SVG 保真、逐图标体积和真实消费者安装测试。
- **必须**确认生成流程没有写入未经授权的 raw SVG。
- **应该**在浏览器中检查图标详情、主题、网格、尺寸和线宽控制。

## 发布

- **必须**记录公共 API、新增资产、弃用和迁移信息。
- **应该**让包版本、生成产物和文档在同一变更中发布。
- **禁止**发布未生成、未验证或与元数据不一致的资产。
