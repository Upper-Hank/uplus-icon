## 命名目标

正式名称是文件系统、元数据、单图标路径和具名组件之间的稳定标识。名称应描述图标的语义，而不是当前视觉样式或某个业务页面。

- **必须**使用小写 ASCII 字母、数字和单个连字符组成 kebab-case。
- **必须**使用行业通用、简短且可被产品团队理解的英文词。
- **应该**优先选择动作或对象本身，例如 `download`、`file`、`arrow-left`。
- **禁止**使用拼音、内部项目缩写、无意义序号或导出工具生成的名称。

## 文件名结构

```text
base[-state][-direction][-variant].svg
```

- **必须**把方向放在基础语义之后，例如 `arrow-left`、`chevron-up`。
- **应该**只在真实存在系列差异时添加状态或变体，例如 `lock` / `unlock`、`save` / `save-alt`。
- **禁止**添加 `icon`、`linear`、`outline`、`24`、`24px` 等全库默认信息。
- **禁止**为了未来可能出现的变体预先制造空层级。

## 尺寸与名称

v1 的 `24×24` 是全库画布约束，不进入名称。`search-24`、`search-small` 和 `search-large` 都不是合法的尺寸表达。

- **必须**让一个 Canonical Name 对应一份 v1 Canonical SVG、一个组件名和一个元数据记录。
- **禁止**用名称编码全库统一的画布尺寸或视觉 Weight。
- **禁止**为了未来可能的尺寸系统预留空变体。

## 名称与组件映射

| SVG | 正式名称 | React 组件 |
| --- | --- | --- |
| `arrow-left.svg` | `arrow-left` | `ArrowLeftIcon` |
| `save-alt.svg` | `save-alt` | `SaveAltIcon` |

- **必须**由生成器完成映射，不能手工指定不同组件名。
- **禁止**让同一 SVG 通过多个正式名称生成重复组件。

## 同义词与别名

- **必须**把历史名称和常用同义词写入 `aliases`，而不是复制 SVG。
- **应该**让别名解决真实检索需求，例如 `remove` 可以指向 `trash`。
- **禁止**让别名与任何正式图标名冲突。
- **禁止**用别名表达分类、风格或临时业务活动。

## 改名与兼容性

正式改名会改变文件路径、正式名称和具名组件，属于公共 API 变化。

- **必须**先确认新名称显著提升准确性，并检查现有消费者。
- **必须**记录迁移方式、弃用周期和发布说明。
- **应该**通过元数据别名保留搜索兼容；组件兼容需要明确的弃用导出方案。
- **禁止**仅为语言偏好或微小措辞差异批量改名。
